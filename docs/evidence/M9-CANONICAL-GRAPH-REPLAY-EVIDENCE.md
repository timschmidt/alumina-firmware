## Canonical artifact and verifier

`CanonicalGraphDeploymentReplayEvidence1` owns the complete immutable bytes and
their SHA-256 digest. `GraphDeploymentReplay::evidence()` exposes that artifact;
the existing `evidence_digest()` is now a projection from it, so the four
previously qualified TinyBee evidence identities remain unchanged.

The `ALGRREP1` format commits:

- device, capability, active configuration, implementation registry, graph-IR
  content, and complete package identities;
- transaction ID, run ID, exact start cycle, and all three replay limits;
- every requested exact cycle, safety-admission bit, typed resource identity,
  and available/unavailable Boolean state;
- every resource call in actual firmware-provider order; and
- each complete `GraphReleaseReport` or terminal first-cause
  `GraphExecutionError`.

All fixed integers are little-endian. Input resource samples are sorted by
canonical typed identity, while observed provider reads retain executor order.
The absolute byte ceiling is 6,525,156 bytes, derived from 4,096 releases, 256
input samples per release, 64 provider reads per release, and the maximum
completed result record. Both construction and import enforce it.

`verify_graph_deployment_evidence_bytes` performs these checks before accepting
an artifact:

1. caller admission policy and absolute byte size before hashing;
2. claimed SHA-256 identity;
3. magic, complete target/deployment identity, declared hard bounds, input
   tags, sorted/distinct resources, and bounded counts;
4. ordinary replay validation, including nonempty strictly increasing cycles;
5. fresh installation, prepare/activate/observe, and release through new
   `FixedGraphServiceActor` and `FixedGraphRealtimeActor` instances using the
   caller-supplied static image palettes; and
6. exact equality of every newly generated byte and the claimed digest.

The imported result suffix is never converted into execution authority. Fresh
actors regenerate it. A changed output with its old digest fails before decode;
the same changed output with a recomputed digest fails the byte-for-byte replay
comparison. Unsorted input records, foreign identities, limit escalation,
truncation, and over-hard byte lengths have separate fail-closed results.

The complete format is documented in the interface at
`docs/GRAPH-DEPLOYMENT-REPLAY-V1.md`.

## TinyBee transactional UI

`TargetResourceDeployment` retains the exact lowering report and both complete
artifacts. A selector edit still commits only after the actual actors reproduce
all four conjunction cases and the unavailable-first-input fault. Native and
WASM file controls now expose:

- `success ALGRREP1 evidence`: exact current bytes, `.algrrep` import/export;
- `fault ALGRREP1 evidence`: exact current bytes, `.algrrep` import/export; and
- visible artifact sizes and current digest prefixes.

Import supplies the current artifact's digest, target tuple, lowering report,
TinyBee opcode/resource palettes, and interactive bounds to the raw verifier.
It accepts only a fresh replay equal to the current artifact. Success or failure
changes only the human-readable status line; it cannot mutate the draft,
lowered package, selected resources, origin persistence, device session, or
physical state.
