## Fixed implementation authority

`GraphSimulationRegistry` is distinct from both the saved structural document
and `GraphNodeRegistry`. It maps exact audited node kind/version identities to
one of only three parameter/state-free behaviors:

- `ExternalStreamSource`, whose exact samples are caller authority;
- `LatestRateTransition`, which executes the already-audited
  `LatestAtOrBeforeSourceFirst` contract; and
- `StreamSink`, which requires one connected bounded Stream input and models no
  side effect.

Construction canonicalizes implementation order, rejects duplicate or unknown
kinds and contradictory schema shapes, and derives an `ALSI` V1 SHA-256 identity
from analysis limits, every audited node schema, and every fixed binding. A
simulation result separately binds that registry identity and the canonical
`ALGR` graph digest, so neither structural nor implementation authority may be
substituted.

Every document node must resolve to one fixed implementation and must be placed
in `HostExact`. Service/Realtime placement fails before evaluation. All modeled
Stream clocks must share the independent root selected by the inclusive
simulation horizon; a derived clock cannot masquerade as a root, and a second
independent root cannot be ordered under the chosen horizon.

## Exact deterministic execution

Caller samples retain source endpoint, source-clock tick, monotonic sequence,
and one exact typed sample. Caller vector order is not semantic authority:
samples are canonicalized by endpoint, tick, and sequence. Duplicate or
regressing per-source tick/sequence, wrong sample type, unknown source, or a
sample after the exact horizon rejects.

All event-time comparisons are `hyperreal::Rational` values measured in the
selected root clock. Transition chains are evaluated only after their upstream
Stream is available. At each target tick, the implementation consumes all
source samples whose exact root time is less than or equal to the target time,
then emits the newest. Thus every coincident source tick is processed first.
Tick zero requires a real source sample; no implicit initial value is created.

The simulator enforces the audited input queue capacity over every due interval
and over any unconsumed tail inside the horizon. Generated Stream sequences are
their target-clock ticks. Final trace ordering is exact root time, then origin,
endpoint, and sequence, so equivalent caller orderings produce identical
results.

The interactive policy independently limits caller samples to 65,536, complete
trace entries to 131,072, ticks generated by one transition to 1,000,000, the
inclusive root horizon to 1,000,000 ticks, and canonical trace input to 16 MiB.
Zero limits and every exceeded bound fail closed.

## Canonical trace and independent replay

`ALGT` V1 uses a fixed little-endian header containing format magic/version,
flags, graph digest, simulation-registry digest, horizon root/tick, and bounded
entry count. Every entry retains origin, node/port endpoint, clock, tick,
sequence, and a length-delimited canonical typed value. Typed values reuse the
`ALGR` exact encoder and are accepted only when decode/re-encode is identical.

Replay does not trust recorded node outputs. It bounds and decodes the trace,
extracts only external source samples, independently reruns the fixed simulator,
re-encodes every entry, and requires byte-for-byte equality with the input.
Trailing data, changed implementation identity, changed value, noncanonical
typed value, any strict prefix, or any independently divergent output rejects.

The representative 1,200-root-tick fixture derives a 1,000 Hz source and 600 Hz
target. Source ticks 0 through 8 produce target ticks 0 through 5 from source
indices `[0, 1, 3, 5, 6, 8]`. Its canonical trace is 658 bytes with SHA-256:

```text
4e0dbaec5495e96a1f472c218a83e8f441118c8a68c4bd94b77516b2d61b773a
```
