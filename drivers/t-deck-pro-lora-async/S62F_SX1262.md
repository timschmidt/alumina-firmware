# S62F/SX1262 communication reference

The T-Deck Pro's S62F module contains a Semtech SX1262 LoRa transceiver. The ESP32-S3 is the SPI controller and must coordinate four additional signals: active-low reset, BUSY, DIO1, and the board-level radio enable.

## Board interface

| Signal | GPIO | Role |
| --- | ---: | --- |
| SCK / MOSI / MISO | 36 / 33 / 47 | Shared SPI bus |
| NSS | 3 | Radio chip select |
| BUSY | 6 | High while the transceiver cannot accept a command |
| NRESET | 4 | Active-low reset |
| DIO1 | 5 | Mapped packet/timeout interrupt |
| enable | 46 | Board-level radio power enable |

SPI uses mode 0. Keep NSS asserted for the complete command transaction and wait for BUSY to deassert before issuing the next command.

## Initialization

The board wrapper currently:

1. resets and calibrates the SX1262;
2. selects LoRa packet mode and the high-power SX1262 PA path;
3. configures spreading factor, bandwidth, coding rate, and sync word from `LoraConfig`;
4. uses a fixed 868 MHz RF frequency, +22 dBm output, 200 µs PA ramp, 15-symbol preamble, variable header, and CRC disabled;
5. configures a 2.4 V TCXO with a 5 ms startup delay;
6. maps `TxDone`, `RxDone`, and `Timeout` to DIO1; and
7. sets over-current protection to 140 mA.

Frequency, power, CRC, and regional policy are not yet fields in `LoraConfig`. Applications must not assume the defaults are legal in every jurisdiction.

## Transmit and receive

`LoraRadio::send` writes at most 255 bytes and starts a transmit with a two-second timeout. Completion is reported through the low-level driver.

`LoraRadio::receive` clears stale IRQs, starts a five-second receive, waits on DIO1, and then reads IRQ and buffer status. It returns `Ok(0)` for a timeout, copies a completed packet into the caller's buffer, and returns `Err(())` for unexpected IRQs or undersized buffers.

After handling an IRQ, clear the corresponding flags before the next operation. BUSY and DIO1 serve different purposes: BUSY gates command acceptance; DIO1 reports configured radio events.
